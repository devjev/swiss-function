Chat on a phone, with its on-screen keyboard. Return breaks the line and the send key sends where the primary pointer is a finger (`enterSends`, `"auto"` by default; Ctrl+Enter or Cmd+Enter sends either way), and the soft keyboard's Return says which. Sending keeps the focus in the field, so the keyboard stays up. With a finger the chat raises no keyboard on its own: the editor no longer takes the focus on mount, when a run ends, on the jump-to-latest label, or after a prompt answered by a tap. A tap anywhere on the editor block focuses the field. `[stop]` stands in the working rule for Escape. The status lines step aside while the keyboard is up for the chat's field. A scroll that reaches the transcript's top or end no longer carries on into the page. `ChatDrawer` pads its panel by what the keyboard covers and what the browser panned out while a keyboard is open, so its header stays in view and its editor sits on the keyboard. Fixed: in a narrow container (a phone, where the panel overlays the app) full screen stayed inside the container; it fills the window. New entry `lib/keyboard`: `useVisibleInsets`, `useKeyboardOpen` and their pure forms, for a full-screen page of the host's own. Refs #111, #110.
