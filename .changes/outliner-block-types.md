Outliner: block types, read from a block's text (issue #105). **Text blocks:** `# ` / `## ` / `### ` headings (Mod+Alt+1 to 3), `> ` quotes (Mod+Shift+.), `> [!note]` / `[!tip]` / `[!warning]` / `[!danger]` callouts, `---` dividers, fenced code blocks (Enter and Tab stay inside the fence), and `1. ` numbered items that continue on Enter and renumber by place. **Tasks:** `[/] ` in progress and `[-] ` cancelled, a count of done tasks on their parent (`2/5`), and `@2026-11-25` due dates as a chip that opens a calendar (late dates on open tasks take the danger tone). **Structured blocks:** `key:: value` properties (new export `blockProperties`), an image alone in a block with a draggable width (`![alt|320](url)`), `{{table}}` and `{{kanban}}` over the block's children (cards drag between columns), and `{{embed ((id))}}`, the referenced block shown again and editable in place. New prop `onUpload` for pasted and dropped files; new CSS variable `--sf-outliner-key-width`. **Changed behaviour:** blocks whose text begins with these markers now render as the type (a `1. ` number is rewritten to its place in the list on the next edit), a pasted ordered list keeps its numbers, and `@YYYY-MM-DD` renders as a chip. Fixed: the `#[[Two Words]]` tag pattern missed its Unicode escapes.
