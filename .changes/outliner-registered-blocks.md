Outliner: registered block types and block commands (issue #105, tier 3). New prop `blockTypes`: an app registers a type as `{ name, aliases?, match?, render, command? }`, matched as `{{name args}}`, as a fenced block in a language, or by a function, and asked before the built-in types. A type can also declare `inline` (`{ open, close?, render }`), a span it renders inside any block's text. New entry `@tarassov-ch/swiss-function/outliner-blocks` with six types, most of which take the app's engine: `createQueryBlockType` (`{{query words}}`, with `searchBlocks` as a plain text search; it waits 200ms after the last change to the tree before it runs again, `debounce` sets the wait), `createMathBlockType` (`$$ ... $$` as a block and `$x$` inside a line, set by KaTeX, which is a new dependency, loaded with its stylesheet on first use), `createDiagramBlockType` (a fenced `mermaid` block), `createDataBlockType` (a fenced `csv`, `tsv` or `json` block as a `DataTable`), `createCodeBlockType` (a fenced block edited in a `CodeEditor`) and `createLinkPreviewBlockType` (a block that is one URL). `/` now lists block commands (Heading 1 to 3, Task, Numbered list, Quote, Note, Warning, Code block, Divider, Table, Board, Embed, and a registered type's command), after the app's own entries; `commands={false}` turns them off. A completion entry can carry `onSelect` and run an action. New exports from the Outliner entry: `useOutlinerTree`, `fenceBody`, `fenceSource`, types `OutlinerBlockType` and `OutlinerBlockProps`. The highlighted entry of a long completion list now scrolls into view. **Changed behaviour:** typing `/` at the start of a word opens the command list even without `completions`.
